# 尺寸、m 和匹配组

## 原始电路有没有 m

**没有。**

原始 LTspice 网表 `src/AHLowVoltageOpAmp.net` 的 MOS 行只有：

```text
M13 Output N003 N001 N001 AhP l=2e-6 w=640e-6
```

没有 `m=`，也没有 `nf=`。LTspice 默认：

```text
m = 1
```

所以原始 `w=640e-6` 就是 **640 µm 总宽度**，不是每 finger 宽度。  
本地适配的 `opamp.sp` 也保持 `m=1`，没有额外乘 m。

`.asc` 里的 `SYMATTR Value2 l=2e-6 w=...` 同样只有 `l` 和 `w`，没有 `m`。

## 匹配组检查

### 15, 3, 4

```text
M15 = 128/2
M3  = 64/2
M4  = 64/2
```

比例 **2 : 1 : 1**。  
可以用 **64/2 为单位**：M15 做 2 个 finger，M3/M4 各 1 个。  
这是整数比，适合 common-centroid / dummy。

### 16, 5, 10

```text
M16 = 162/2
M5  = 162/2
M10 = 194/2
```

比例：

```text
M10 / M16 = 194 / 162 = 1.1975...
```

**不是整数比**；接近 1.2，但不是精确 1.2（1.2×162=194.4）。  
如果这是有意的 1.2 电流比，需要确认误差是否可接受；如果要严格匹配，建议：

- 把 M10 改成 162/2（1:1:1）；或
- 把 M10 改成 194.4/2（如果工艺/版图允许小数 W）；或
- 明确这是 ratio device，按 1.2 比例做，不用整数 unit。

按 2 µm 的 unit 拆：162/2 = 81 个 2 µm finger，194/2 = 97 个，finger 数很多，实际版图不友好。  
**这一组是当前最需要你确认的匹配组。**

### 1, 2

```text
M1 = M2 = 80/2
```

1:1，直接 common-centroid / 同方向。

### 8, 9

```text
M8 = M9 = 109/2
```

1:1。

### 6, 7

```text
M6 = M7 = 240/2
```

1:1。

### 11, 12, 13

```text
M11 = 240/2
M12 = 240/2
M13 = 640/2
```

比例 **3 : 3 : 8**（用 80/2 为单位）：

- M11 = 3 × 80/2
- M12 = 3 × 80/2
- M13 = 8 × 80/2

这是整数比，适合匹配；M13 是输出上拉电流源，W 是 M11/M12 的 8/3 倍。

## 结论

- 原始电路 **没有 m 参数**，所有管子默认 `m=1`；
- 原始 `w` 是总宽度，不是 finger 宽度；
- 15/3/4、11/12/13 可以找到整数 unit；
- 1/2、8/9、6/7 是 1:1；
- **16/5/10 的 194/162 不是整数比，需要你确认 1.2 比例是否有意**。
