# 问题：模拟与版图之间到底丢了什么

## 1. 三个角色，三种语言

| 角色 | 关心什么 | 手里有什么 |
| --- | --- | --- |
| 模拟设计 | 增益、带宽、噪声、offset、稳定性、功耗、面积 | 原理图、W/L、仿真结果、脑中的匹配/布局意图 |
| 版图设计 | 匹配、对称、寄生、电流密度、DRC/LVS、面积 | 版图工具、规则文件、floorplan、口头/邮件需求 |
| AI agent | 可读的上下文、可验证的输出 | 网表、注释、规则包、历史记录 |

问题不是任何一方“不专业”，而是**原理图只记录了电气连接和尺寸，没有记录布局意图**。W/L 能告诉版图“这个管子多大”，但不能告诉它“这两个管子必须共质心”“这个管子是 dummy，不要接信号”“这个模块要留 8% 给 PEX 后的修补”。

## 2. 四个具体的丢失点

### 2.1 面积：只有一个数，没有结构

早期评估面积通常靠：

- 把 W×L 加起来乘一个经验系数；
- 等版图工程师画完再量；
- 用上一个项目的面积拍脑袋。

问题是这个数**不可解释**：不知道哪类器件占大头，不知道 dummy/guard ring/电容占多少，也不知道误差范围。于是无法支持“用面积选架构”这种早期决策。

### 2.2 布局：布局草图在一个人脑子里

模拟工程师通常知道：

- 输入对要放中间，跨对称轴；
- 电流镜要放在上面，尾电流在下面；
- 输出级在右边，补偿电容靠近输出；
- 哪些管子要 interdigitated / common-centroid；
- 哪些地方要留 routing channel。

但这些信息往往只在评审时口头说一遍，版图工程师再按自己的理解画。第一版 floorplan 出来之后，双方才发现“原来你说的对称是这个意思”。

### 2.3 后期改动：PEX 之后才出现

PEX 后常见的“低级别修改”：

- 加 boundary dummy；
- 加 dummy mirror branch / dummy switch；
- 加 decap；
- 把一个大管子拆成更多 finger；
- 加 guard ring / shielding；
- 调整输出金属宽度。

这些改动电气上不复杂，但会让已经验证过的 schematic/layout 对失效，模拟工程师需要重新跑仿真、重新确认，非常消耗情绪和时间。

### 2.4 沟通：没有共享的、可版本化的中间物

邮件、截图、白板、口头结论都无法 diff、无法 review、无法在下一个项目复用。AI 如果只看网表，也拿不到这些意图；如果只看聊天记录，又无法保证规则正确。

## 3. a2l 的切入点

把“意图”变成**结构化、可版本化、可被 AI 和版图工具消费**的数据链：

```text
schematic annotations
        │
        ▼
role / match / group / layout
        │
        ├──► area model ──────────────► area report + range
        │
        ├──► floorplan intent ────────► floorplan sketch SVG + JSON
        │
        └──► layout-delta planner ────► dummy/decap/reserve manifest
                                              │
                                              ▼
                                        HANDOFF.md / review
```

三个产物共享同一套 role 和 rule，所以面积、布局、后期改动不会各说各话。

其中最难、也最适合做 AI-native 表达的是 **Layout Guideline**：把 Principle / Module / Pattern / Case 编译成一页 Layout Card。见 [`docs/08-ai-layout-guideline.md`](08-ai-layout-guideline.md)。

## 4. 设计原则

1. **名字是主参考，属性是确认层**：真实仿真/验证网表通常只有器件名；显式 `role=` 用于人工确认/覆盖。
2. **规则是数据**：每个面积数字都能追溯到 rule key；公司规则可以替换、版本化、校准。
3. **提议而不是修改**：delta 不自动改原理图，必须由人 accept/reject。
4. **早期估计给区间**：不假装 signoff 精度，明确 ±范围和使用边界。
5. **确定性核心 + AI 语义层**：几何/规则计算可审计；AI 负责读拓扑、补 role、解释 delta、把评审意见结构化。
6. **角色表和规则归模拟工程师所有**：AI 可以提议 role、检查覆盖、解释结果，但不能自行批准 taxonomy 或改 rule 数值。
7. **人仍然是决策者**：AI 不建议具体 DRC 数值，不替工程师做架构取舍。

## 5. 成功指标

如果一个团队要落地这套东西，建议跟踪：

| 指标 | 目标 |
| --- | --- |
| 角色语义覆盖率 | > 95% 的器件有名字 token 或显式 role |
| 面积预测误差 | 早期 ±30–50%，校准后 ±20% |
| floorplan 评审轮次 | 从 3–4 轮降到 1–2 轮 |
| PEX 后“清单外”改动 | 逐季度下降 |
| 评审准备时间 | 从半天降到半小时 |
| 跨项目复用 | 规则包/模板可复用 |

## 6. 明确不解决

- 不做电路拓扑生成；
- 不做尺寸优化；
- 不做 DRC/LVS；
- 不做寄生提取；
- 不替代任何签核工具；
- 不处理未脱敏的工艺厂机密数据。

a2l 只解决“意图丢失”这一段，并且尽量把这一段做扎实。
